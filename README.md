# Unity CI/CD

A CI/CD setup for automating **Unity project builds** using GitHub Actions. This repository provides the foundation for automatically validating, building, and managing Unity projects through a continuous integration and delivery workflow.

## 🚀 Overview

The goal of this repository is to demonstrate how to configure a Unity project for automated builds using GitHub Actions.

The CI/CD pipeline can be used to:

- Automatically trigger builds when changes are pushed.
- Build Unity projects without manually opening the Unity Editor.
- Handle Unity licensing in the CI environment.
- Support Git LFS for large Unity assets.
- Store build artifacts generated by the pipeline.
- Provide a repeatable build environment for the team.

## 🛠️ Requirements

Before running the project locally, install:

- Unity Hub
- The Unity Editor version used by the project
- Git
- Git LFS

Check Git LFS:

```bash
git lfs install
```

Clone the repository:

```bash
git clone https://github.com/DURKESH-KUMAR/Unity-CICD.git
cd Unity-CICD
```

If the repository uses Git LFS:

```bash
git lfs pull
```

## 🔐 Unity License

The CI environment needs a valid Unity license to execute Unity Editor commands.

For CI/CD, **do not commit your local Unity license file (`.ulf`) to the repository**.

Instead, store sensitive Unity licensing information using **GitHub Actions Secrets** or the appropriate Unity CI authentication mechanism.

Never commit credentials, access tokens, passwords, or license files containing sensitive information.

## 📦 Git LFS

Unity projects can contain large binary files such as:

- `.psd`
- `.fbx`
- `.wav`
- `.mp3`
- `.mp4`
- `.png`
- `.jpg`
- Large Unity assets

Git LFS can be used to manage these files efficiently.

Initialize Git LFS:

```bash
git lfs install
```

Track a file type:

```bash
git lfs track "*.psd"
```

Then commit the generated `.gitattributes` file:

```bash
git add .gitattributes
git commit -m "Configure Git LFS"
```

## ⚙️ GitHub Actions

The CI workflow is located under:

```text
.github/workflows/
```

A workflow can be configured to run automatically when changes are pushed:

```yaml
on:
  push:
    branches:
      - main
```

You can also configure workflows for:

- Pull requests
- Manual builds
- Release builds
- Development builds
- Android builds
- Windows builds
- Other supported Unity build targets

## 🏗️ Build Artifacts

After a successful CI build, the generated Unity build can be uploaded as a GitHub Actions artifact.

This allows the team to download and test the generated build without building the project locally.

Example:

```text
Git Push
   ↓
GitHub Actions
   ↓
Unity Build
   ↓
Build Artifact
   ↓
Download / Test
```

## 🌿 Recommended Branch Strategy

A simple workflow can use:

```text
main
 │
 ├── develop
 │    ├── feature/*
 │    └── bugfix/*
 │
 └── release/*
```

Recommended approach:

- `main` → stable/production code
- `develop` → active development
- `feature/*` → new features
- `bugfix/*` → bug fixes
- `release/*` → release preparation

## 🧪 Pull Request Validation

CI can also be configured to automatically validate pull requests.

For example:

```text
Pull Request
     ↓
GitHub Actions
     ↓
Checkout
     ↓
Unity Setup
     ↓
Unity Build/Test
     ↓
   ┌───────────────┐
   │               │
 Success          Failure
   │               │
   ▼               ▼
Merge            Fix Issues
```

This helps prevent broken Unity projects from being merged into the main branch.

## 🔒 Security

Never commit sensitive information such as:

```text
Unity license files
API keys
Access tokens
Passwords
Keystore passwords
Signing credentials
Cloud credentials
```

Use **GitHub Actions Secrets** for sensitive CI/CD configuration.
